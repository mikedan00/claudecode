# Browser Swarm PoC 실행 방법과 사용 설명서

Browser Swarm PoC는 브라우저 탭 하나를 노드 하나로 삼아 여러 기기의 GPU와 RAM을 묶고, P2P 분산 LLM 추론을 실험하고 관리하는 도구입니다. 설치할 것은 없고 `p2p-llm-poc/index.html` 파일 하나로 동작합니다.

기준 환경은 **Windows 11 노트북 + RTX 4070 Laptop 8GB + Chrome 또는 Edge**입니다.

---

## 1. 실행 방식 고르기

실행 방식은 두 가지이며, 할 수 있는 일이 다릅니다.

| | A. Sites에서 열기 | B. 로컬에서 열기 |
|---|---|---|
| 주소 | https://claude.ai/artifact/T1pyDrPbGPHL3ZNTicAsNN | `http://localhost:8000` (또는 파일 직접 열기) |
| 노드 연결 | room 중계, 자동 | WebRTC 직접 연결, 연결 코드를 주고받음 |
| 데이터 저장 | 공유 DB (참여자 모두가 같은 데이터를 봄) | 이 브라우저에만 저장 |
| WebLLM 실추론 | 가중치 다운로드가 막힐 가능성이 높음 | 가능 |
| 지연시간 측정 | Sites 서버 중계 지연이 포함됨 | 기기 사이의 실제 지연 |
| 적합한 용도 | 실험 설정, 결과, PoC 현황을 팀이 함께 관리 | 실측 P2P 지연, 실제 모델 실행 |

Sites 페이지 안에서는 WebRTC가 차단됩니다. 그래서 직접 P2P 연결과 실추론은 B 방식으로 하고, 결과는 JSON으로 내보내 A에 가져오는 흐름을 권장합니다(8장).

## 2. A. Sites에서 실행하기

1. 위 주소를 Chrome이나 Edge에서 엽니다. claude.ai에 로그인되어 있어야 합니다.
2. 처음에는 소유자만 열 수 있습니다. 다른 사람과 함께 쓰려면 페이지의 **공유(Share)** 메뉴에서 참여자를 추가합니다.
   - 다른 노드에 작업을 보내거나 받으려면 참여자에게 **Contributor 이상** 권한이 있어야 합니다.
   - Viewer 권한으로는 노드 목록과 기록만 볼 수 있습니다.
3. 각 참여자가 같은 주소를 열면 **노드** 화면에 서로가 자동으로 나타납니다.
4. 상단 칩에서 `room 연결됨`, `저장: 공유 DB`가 보이면 준비가 끝난 것입니다.

> 같은 기기에서 탭을 두 개 열면 노드 두 개가 됩니다. 연결 테스트를 혼자 할 때 유용합니다.

## 3. B. 로컬에서 실행하기 (Windows 11)

### 3.1 파일 받기

둘 중 편한 방법을 고릅니다.

- **Git 사용:**
  ```powershell
  git clone https://github.com/mikedan00/claudecode.git
  cd claudecode
  git checkout claude/p2p-distributed-llm-webapp-dvb7s3
  cd p2p-llm-poc
  ```
- **파일만 받기:** GitHub의 해당 브랜치에서 `p2p-llm-poc/index.html`을 열고 **Download raw file**로 저장합니다.

### 3.2 로컬 서버로 열기 (권장)

WebGPU와 WebLLM은 보안 컨텍스트(https 또는 localhost)에서만 안정적으로 동작합니다. `index.html`이 있는 폴더에서 다음을 실행합니다.

```powershell
# Python이 있으면
python -m http.server 8000

# Node.js가 있으면
npx serve -l 8000
```

그다음 브라우저에서 `http://localhost:8000`을 엽니다.

> 파일을 더블클릭해 `file://`로 열어도 노드 연결과 시뮬레이션은 됩니다. 하지만 WebLLM이 모델 캐시를 저장하지 못해 실패할 수 있습니다.

> **주의:** 다른 기기에서 `http://192.168.x.x:8000`처럼 IP 주소로 접속하면 보안 컨텍스트가 아니어서 WebGPU가 꺼집니다. 노드마다 자기 기기에서 `localhost`로 열어야 합니다.

### 3.3 RTX 4070을 브라우저에 연결하기

노트북은 기본적으로 내장 GPU를 쓰는 경우가 많습니다.

1. **설정 > 시스템 > 디스플레이 > 그래픽**으로 갑니다.
2. Chrome 또는 Edge를 선택하고 **고성능(NVIDIA GeForce RTX 4070 Laptop GPU)** 으로 지정합니다.
3. 브라우저를 완전히 종료했다가 다시 엽니다.
4. 주소창에 `chrome://gpu`(Edge는 `edge://gpu`)를 열고 **WebGPU: Hardware accelerated**인지 확인합니다.
5. 측정할 때는 **충전기를 연결**합니다. 배터리 모드에서는 GPU 클럭이 크게 떨어집니다.

## 4. 처음 실행했을 때 할 일

**노드** 화면에서 내 노드부터 설정합니다.

1. **노드 이름:** 다른 사람이 알아볼 수 있게 정합니다. 예: `민수-4070노트북`
2. **하드웨어 프로필:** 기본값은 `RTX 4070 Laptop 8GB (기준)`입니다. 기기에 맞게 바꿉니다. 프로필을 바꾸면 VRAM 값도 함께 바뀝니다.
3. **VRAM, 시스템 RAM:** 브라우저는 VRAM 용량을 알려주지 않으므로 직접 입력합니다.
4. **WebGPU 다시 감지:** 어댑터 이름, `maxBuffer`, f16 지원 여부를 읽습니다. 세션 로그에 "내장 GPU 어댑터가 선택됐습니다"가 나오면 3.3을 다시 확인하세요.
5. **GPU 대역폭 측정:** 128MiB 버퍼를 반복 복사해 GB/s를 잽니다. 측정값의 60%가 속도 예측에 쓰입니다. 4070 Laptop 사양은 256 GB/s입니다.
6. **다른 노드의 작업 받기:** 이 노드가 남의 요청을 처리할지 정합니다. 끄면 작업을 보내기만 합니다.

### WebLLM 실추론 (선택)

1. **노드** 화면에서 **WebLLM 실추론 (선택)** 을 펼칩니다.
2. 모델을 고르고 **불러오기 시도**를 누릅니다. 처음에는 가중치를 내려받느라 시간이 걸립니다. 0.5B는 수백 MB, 8B는 약 5GB입니다.
3. 상태가 `로드 완료 · 실추론 가능`이 되면, 이 노드에 배정된 같은 모델 요청은 실제로 실행됩니다. 실행기 칸에 `webllm`으로 표시됩니다.
4. 다른 모델의 요청이나 레이어 분할 요청은 계속 시뮬레이터로 처리합니다.

## 5. 노드 연결하기

### 5.1 Sites: 자동

같은 주소를 열기만 하면 됩니다. 2장을 참고하세요.

### 5.2 로컬: WebRTC 수동 시그널링

두 사람(A, B)이 각자 로컬로 연 상태에서 **연결** 화면을 엽니다. 연결 코드는 메신저 등 아무 경로로나 주고받으면 됩니다.

| 순서 | 누가 | 할 일 |
|---|---|---|
| 1 | A | **1. 오퍼 만들기**를 누르고 **복사**한 뒤 B에게 보냅니다 |
| 2 | B | 받은 코드를 **받은 오퍼 코드를 붙여넣기** 칸에 넣고 **2. 응답 만들기**를 누릅니다 |
| 3 | B | **복사**를 눌러 응답 코드를 A에게 보냅니다 |
| 4 | A | 응답 코드를 **응답 코드를 붙여넣기** 칸에 넣고 **3. 응답 적용**을 누릅니다 |
| 5 | 둘 다 | 연결 화면 아래 칩이 `connected`가 되고, 노드 화면에 상대가 나타납니다 |

- 노드가 3개 이상이면 연결하고 싶은 두 노드마다 위 과정을 반복합니다. 작업을 보내는 노드(코디네이터)는 모든 작업 노드와 연결되어 있어야 합니다.
- 같은 Wi-Fi나 LAN에서는 대부분 바로 연결됩니다. 회사망처럼 대칭 NAT 뒤에 있으면 연결이 안 될 수 있으며, 이때는 TURN 서버가 필요합니다(현재 미지원).
- 오퍼를 다시 만들면 이전 오퍼는 쓸 수 없습니다. 응답은 반드시 가장 최근 오퍼에 대해 만들어야 합니다.
- 30초 동안 응답이 없는 WebRTC 노드는 목록에서 빠집니다.

## 6. 화면별 사용법

### 개요
- 상단 타일에 노드 수, 총 VRAM, 브라우저 가용 VRAM 추정, 평균 RTT, 큐 상태가 나옵니다.
- **기준 환경 제약**에서 8GB 노트북으로 어떤 모델까지 단독 적재가 가능한지 봅니다.
- **PoC 진행** 막대는 단계별 상태(완료, 진행 중, 막힘)를 색으로 보여줍니다.
- **세션 로그**에는 노드 합류·이탈, 작업 배정, 실패, 재시도가 시간순으로 쌓입니다.

### 노드
- 노드 카드마다 연결 방식, GPU, VRAM과 가용 추정치, maxBuffer, 측정 대역폭, RTT 중앙값, 핑 성공률과 지터, 처리 건수가 나옵니다.
- **안정성 배지**는 최근 핑 20회를 기준으로 계산합니다.
  - `안정`: 점수 0.85 초과
  - `불안정`: 0.6 초과
  - `나쁨`: 그 이하
  - 점수 = 핑 성공률 × 지터 감점 (지터가 RTT에 비해 클수록 감점)
- 작은 그래프는 최근 RTT 추이이고, 빨간 막대는 핑 손실입니다. 핑은 3초마다 보내고, 5초 안에 답이 없으면 손실로 셉니다.
- **단독 적재 가능**은 그 노드 혼자 올릴 수 있는 모델 목록입니다.

### 작업 큐
1. 프롬프트, 모델, 분배 전략, 토큰 수, 개수, 동시 실행 수, 배속을 정합니다.
2. **큐에 추가**를 누르면 바로 분배가 시작됩니다. 버튼 옆에 다음 배정 노드가 미리 표시됩니다.
3. **일시 정지**는 새 요청 배정만 멈추고, 실행 중인 요청은 끝까지 갑니다.
4. **현재 큐를 실행 기록으로 저장**은 수동으로 넣은 요청 중 끝난 것을 실행 기록 하나로 묶어 저장합니다. 실험 설정에서 실행한 요청은 자동으로 저장됩니다.

**분배 전략**

| 전략 | 동작 | 쓰임 |
|---|---|---|
| 내 노드만 | 이 탭에서만 실행 | 단일 노드 기준선 |
| 라운드 로빈 | 모델을 올릴 수 있는 노드에 차례로 배정 | 가장 단순한 비교군 |
| 부하 최소 | 실행 중인 작업이 가장 적은 노드 | 동시 요청이 많을 때 |
| 지연 최소 | RTT가 가장 낮은 노드 | 지연이 큰 망에서 |
| 예상 속도 가중 | 예상 tok/s ÷ (1 + 현재 부하)가 가장 큰 노드 | 이기종 노드 혼합 |
| 레이어 분할 | 가용 메모리가 큰 노드부터 골라 레이어를 메모리 비율로 나눔 | 한 노드에 안 들어가는 모델 (예: 14B) |

요청이 실패하거나 시간 초과가 나면 그 노드를 빼고 다시 배정합니다. 수동 큐는 1회, 실험은 설정한 횟수만큼 재시도합니다.

**배속:** 시뮬레이션은 예측된 시간만큼 실제로 기다립니다. 5×로 두면 대기 시간이 1/5이 되지만, 표에 나오는 TTFT와 tok/s는 1× 기준 예측값입니다.

### 실험 설정
1. 왼쪽 양식에 이름, 모델, 전략, 요청 수, 동시 실행, 토큰, 배속, 시간 초과, 재시도, 프롬프트, 메모(가설)를 넣습니다.
2. **저장**하거나 **저장 후 실행**을 누릅니다. 실행하면 작업 큐 화면으로 이동합니다.
3. 오른쪽 목록의 카드에서 **실행**(같은 조건으로 재실행), **편집**, **복제**, **삭제**를 할 수 있습니다. 삭제는 두 번 눌러야 됩니다.
4. **WebLLM이 로드된 노드는 실추론 사용**에 체크하면, WebLLM을 불러온 노드에 배정된 요청은 실제로 실행합니다.
5. `[예시]`로 시작하는 설정 3개가 미리 들어 있습니다. 기준선(1B, 내 노드만), 분배(3B, 예상 속도 가중), 분할(14B, 레이어 분할)입니다.

### 실행 기록
- 실행마다 시작 시각, 실험, 모델, 전략, 노드 수, 성공 건수, 평균 TTFT, 평균 tok/s, p95 E2E, 처리량이 한 줄로 나옵니다.
- **로그**를 누르면 그 실행의 노드 구성, 메모, 실행 로그가 펼쳐집니다.
- 왼쪽 체크박스로 실행 **두 개**를 고르면 아래 **비교** 표에 지표가 나란히 나오고, B − A 차이가 좋아졌으면 초록, 나빠졌으면 빨강으로 표시됩니다.

### 모델 비교
- 위 막대그래프는 모델별 측정 평균 tok/s(청록)와 현재 노드 구성 기준 예측값(주황)입니다.
- 첫 표는 모델마다 가중치 크기, 내 노드 적재 여부, 스웜 적재 가능 여부(단독 또는 분할 노드 수), 예측값, 측정값을 보여줍니다.
- 두 번째 표는 모델 × 전략 조합별 측정값입니다.

### PoC 단계
- 0~6단계가 미리 들어 있습니다. 상태(예정, 진행 중, 완료, 막힘)를 고르고, 체크 항목을 표시하고, 메모에 측정값이나 막힌 점을 적습니다.
- 바꾸면 자동으로 저장됩니다. 오른쪽 위에 `저장됨`이 표시됩니다.

### 설계 메모
- SwarmLLM과 현재 설계를 항목별로 비교하는 표입니다. 칸을 고치면 자동 저장되고, **항목 추가**와 삭제가 됩니다.
- **SwarmLLM 열의 처음 내용은 일반적인 스웜형 설계를 가정한 초안입니다.** 실제 SwarmLLM 문서와 대조해 고쳐 주세요.

## 7. 권장 실험 순서

PoC 단계 화면의 0~5단계를 그대로 따라가면 됩니다.

1. **단일 노드 기준선 (0~1단계):** 로컬에서 WebGPU 감지, 대역폭 측정을 하고 Qwen2.5 0.5B를 WebLLM으로 불러옵니다. 실험 `[예시] 기준선`의 모델을 0.5B로 바꿔 실행하고, 실측값과 시뮬레이터 예측을 모델 비교 화면에서 비교합니다.
2. **두 노드 연결 (2단계):** 같은 기기의 탭 두 개로 먼저 연습한 뒤, 기기 두 대를 연결합니다. 10분 정도 두고 노드 카드의 RTT, 손실, 안정성을 기록합니다. Sites(room 중계)와 로컬(WebRTC 직접)의 RTT 차이도 PoC 메모에 적습니다.
3. **요청 분배 (3단계):** 같은 모델, 같은 요청 수로 전략만 바꿔 실험을 여러 개 만들고 실행합니다. 실행 기록에서 두 개씩 골라 처리량과 p95를 비교합니다.
4. **레이어 분할 (4단계):** `[예시] 분할: Qwen2.5 14B`를 실행합니다. 8GB 노트북 두 대면 24레이어씩 나뉩니다. 단일 노드 8B 결과와 비교합니다.
5. **장애 내성 (5단계):** 실험을 돌리는 도중 작업 노드 탭을 닫습니다. 로그에서 `노드 이탈 → 재시도`가 나오고 다른 노드로 재배정되는지 확인합니다.

## 8. 데이터 저장과 이동

- **Sites:** 실험 설정, 실행 기록, PoC 단계, 설계 메모가 공유 DB에 저장되어 참여자 모두가 같은 내용을 봅니다.
- **로컬:** 같은 데이터가 그 브라우저의 localStorage에만 저장됩니다. 브라우저 데이터를 지우면 사라집니다.
- **내보내기:** 실행 기록 화면의 **JSON 내보내기**를 누릅니다. Sites에서는 파일 저장 확인 창이 뜨고, 로컬에서는 클립보드에 복사됩니다(안 되면 아래 상자에 표시됨).
- **가져오기:** **가져오기**를 눌러 JSON을 붙여넣거나 파일을 고른 뒤 **가져오기**를 누릅니다. 같은 ID는 덮어쓰고, PoC 단계와 설계 메모는 가져온 내용으로 바뀝니다.
- **로컬 실측 결과를 팀에 공유하는 흐름:** 로컬에서 실험 → JSON 내보내기 → Sites 페이지에서 가져오기.

## 9. 지표와 예측 방식

| 지표 | 뜻 |
|---|---|
| TTFT | 첫 토큰까지 걸린 시간. 프리필 시간 + 네트워크 RTT |
| tok/s | 디코딩 속도 (생성 토큰 ÷ 디코딩 시간) |
| E2E | 요청 하나의 전체 시간 (TTFT + 디코딩) |
| p95 E2E | 요청의 95%가 이 시간 안에 끝남. 꼬리 지연 |
| 처리량 | 실행 전체에서 초당 생성한 토큰 수 (동시 실행 효과 포함) |
| RTT | 핑 왕복 시간의 최근 10회 중앙값 |

**시뮬레이터의 예측 방식** (추정치이며, 실측으로 보정하는 것이 PoC의 목적입니다)

- 가중치 크기(GB) = 파라미터 수(B) × 4.5비트 ÷ 8 × 1.05
- 디코딩 tok/s = 유효 대역폭 ÷ 맡은 가중치 크기
  - 유효 대역폭 = 측정 대역폭 × 0.6, 측정 전에는 프로필 대역폭 × 실효 비율
- 프리필 속도 = 프로필 연산량 × 실효 비율 ÷ (2 × 파라미터 수)
- 적재 조건: 가중치 + 0.5GB 안팎(런타임, KV 캐시) ≤ VRAM × 가용 비율
  - RTX 4070 Laptop은 가용 비율 0.7로, 약 5.6GB를 가정합니다
- 레이어 분할: 요청한 탭을 중심으로 한 별형 구조를 가정합니다. 토큰마다 각 단계와 한 번씩 왕복하므로, 토큰당 시간 = 단계별 계산 시간의 합 + 단계별 RTT의 합입니다.

## 10. 문제 해결

| 증상 | 원인과 해결 |
|---|---|
| 상단 칩이 `WebGPU 없음` | 3.3의 고성능 GPU 설정 확인. `chrome://gpu`에서 WebGPU 상태 확인. IP 주소로 접속했다면 `localhost`로 열기 |
| 어댑터가 Intel 내장 GPU로 잡힘 | Windows 그래픽 설정에서 브라우저를 고성능으로 지정한 뒤 브라우저 재시작 |
| Sites에서 다른 사람이 노드 목록에 안 보임 | 상대가 같은 주소를 열었는지, 공유 권한이 있는지 확인. 상단 `room` 칩 상태 확인 |
| 작업을 보내면 바로 실패함 (Sites) | 참여자 권한이 Contributor 이상인지 확인 |
| `적재 가능한 노드가 없습니다` | 그 모델을 올릴 수 있는 노드가 없음. 더 작은 모델을 고르거나 레이어 분할 전략을 쓰거나 노드를 추가 |
| WebRTC가 `connecting`에서 멈춤 | 가장 최근 오퍼에 대한 응답인지 확인. 다른 네트워크라면 대칭 NAT일 수 있음(같은 LAN에서 재시도) |
| WebLLM 불러오기 실패 (Sites) | 가중치 다운로드 차단. 로컬 서버(3.2)로 열어서 시도 |
| WebLLM 불러오기 실패 (로컬) | `file://`이면 로컬 서버로 열기. 8B 모델은 VRAM 부족일 수 있으니 더 작은 모델부터 시도 |
| 핑 손실이 많고 `불안정` | Wi-Fi 신호, 절전 모드, 백그라운드 탭 확인. 백그라운드 탭은 브라우저가 타이머를 늦춤 |
| 측정값이 들쭉날쭉함 | 충전기 연결, 다른 GPU 앱 종료, 같은 조건으로 여러 번 실행해 비교 |

## 11. 알려진 제약

- Sites 안에서는 WebRTC가 차단되어 직접 P2P 연결은 로컬 실행에서만 됩니다.
- 브라우저는 VRAM 용량을 알려주지 않으므로 VRAM 값은 수동 입력과 프로필에 의존합니다.
- 레이어 분할은 실측 RTT를 쓰는 시뮬레이션입니다. 실제 블록 단위 WebGPU 실행은 6단계 연구 과제입니다.
- TURN 서버를 지원하지 않습니다.
- 프롬프트가 평문으로 전달되므로 민감한 내용은 쓰지 마세요.
- 같은 조직 참여자끼리 쓰는 것을 전제로 합니다.
